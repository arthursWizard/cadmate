# One active project, a fixed layout, one history folder

The user collaborates on a design by looking at it, in KiCad, FreeCAD and Finder, between your steps. That only works if
there is one current version to look at. Side-by-side versions (`main-v2/`, `main-routed.kicad_pcb`,
`main-hand3.kicad_pcb`, `case/variant-b/`) make the user work out what's new, and every later step has to pick the right
copy. Over a long design this piles up hundreds of superseded files, and the user can no longer tell what's current.

So:

1. **One active project.** Every change is applied to the active project, in place. No copies to "keep the old one".
2. **History is snapshots.** When the current state is worth going back to, `project_snapshot` copies it into
   `history/<YYYYMMDD-HHMM>_<label>/` first, then you change the active files. `project_restore` brings one back.
3. **A fixed layout**, so every file has one place and one depth.

These rules are about your own habits as much as cadmate's tools: hand-made copies, generator scripts that write
`-v2` folders and instructions to another session ("build it as a new folder next to the current one") cause the same
sprawl. Apply them to everything you write and everything you ask another session to write.

## Layout

The shape depends on which tools the design uses, recorded as `"tools"` in `cadmate-project.json`:

- **KiCad and FreeCAD**: each tool's files in its own folder, `kicad/` and `case/` (below).
- **One tool only**: flat. There is no `kicad/` or `case/` level; what would go in it sits at the project root.
  A folder holding only one thing is nesting with no purpose.

Two tools:

```
<project>/
  cadmate-project.json     marker: name, layout version, tools
  README.md                what it is, boards, what to order where, open items, decisions
  CLAUDE.md                these rules in short, for every session working in the folder
  kicad/
    <board>/               one board per folder, every file named after the folder
      <board>.kicad_pro  <board>.kicad_sch  <board>.kicad_pcb  <board>.kicad_dru
      fp-lib-table  sym-lib-table            paths as ${KIPRJMOD}/../lib/...
    lib/                   project libraries shared by the boards
      <project>.pretty/  <project>.kicad_sym  <project>.3dshapes/
  case/                    FreeCAD sources (.FCStd), <part>.step, assembly.step, report.json
    enclosure.json         openings meant to be there, joint limits, heights from the brief (check_enclosure)
    enclosure-check.json   check_enclosure's last report
    renders/
    pcb-models/            <board>.step exported from KiCad, for fitting the case
  fab/<board>/             generated by export_fab: Gerbers zip, BOM, CPL. Regenerate, never edit
  tools/                   generator scripts and their inputs: the design's source code
  docs/                    datasheets, drawings, the user's photos and notes
    brief.md               every requirement the user stated, as a checklist
  history/
    HISTORY.md             index: one row per snapshot, oldest first
    20261031-1213_before-rework/   same relative paths as the project
  .cadmate/work/           scratch: comparisons, temp outputs. Delete when the step is done
```

KiCad only (`"tools": ["kicad"]`): the contents of `kicad/` move up a level, everything else is the same.

```
<project>/
  cadmate-project.json  README.md  CLAUDE.md
  <board>/                 <board>.kicad_pro ... fp-lib-table, paths still ${KIPRJMOD}/../lib/...
  lib/                     <project>.pretty/  <project>.kicad_sym  <project>.3dshapes/
  fab/<board>/  tools/  docs/brief.md  history/  .cadmate/work/
```

FreeCAD only (`"tools": ["freecad"]`): the contents of `case/` sit at the root; no `fab/`.

```
<project>/
  cadmate-project.json  README.md  CLAUDE.md
  <part>.FCStd  <part>.step  assembly.step  enclosure.json  enclosure-check.json
  renders/  pcb-models/
  tools/  docs/brief.md  history/  .cadmate/work/
```

Board folders stay even when there's one board: every board has the same depth, `${KIPRJMOD}/../lib/` works in both
shapes, and the move to `kicad/` later edits no file. A board can't be named after a shared folder (`docs`, `tools`,
`lib`, `fab`, `case`, ...).

Pass `tools` to `project_init` for what the design uses; ask the user when it isn't clear. Without it, `project_init`
goes by the files already there, else makes both. A marker with no `tools` (made before this) is the two-tool layout.

### When a one-tool project gains the other tool

`project_add_tool` (with `kicad` or `freecad`) does it: it snapshots the whole project (`before-add-<tool>`), moves the
existing tool's files from the root into `kicad/` or `case/`, makes the new tool's folders and updates the marker.
Board folders and `lib/` move together, so library and model paths still resolve; nothing inside a file changes. Ask
the user to save and close the files in KiCad and FreeCAD first, and to reopen them from the new place after. Then
update the layout lines in CLAUDE.md and README.md. Don't move the files by hand. `project_check` flags the other
tool's files at the root of a one-tool project and points at `project_add_tool`. cadmate doesn't go the other way
(both to one): if a tool is dropped, ask the user, snapshot, and move the files up yourself.

`project_init` makes it (safe on an existing folder: it only adds). `project_check` lists everything out of place,
each with a fix. Run it before you tell the user a step is done.

Names: lowercase, dashes, no version or state words (`v2`, `final`, `new`, `routed`, `fixed`). A board's name is what
it is (`main`, `sensor`, `power`), not when it was made.

## The brief

`docs/brief.md` holds every requirement the user has stated, in their words, with who said it and when: shapes,
sizes, parts already chosen, angles, looks, things they don't want. Over a design that runs for days, a shape asked for
on day one or a part the user already picked is easy to lose in the conversation; if it isn't written where every later
stage looks, a stage builds something else or asks again.

- Add to it the moment the user states a requirement or makes a choice (decision cards included), not at the end.
- Re-read it at the start of each stage (schematic, PCB, fab, case) and before showing the user a result.
- Tick an item only once you have checked the design against it (render, DRC, measurement).
- `project_check` returns the open items under `brief`. When you report a stage done, say which items are met, which
  aren't yet and why.
- A value you assume (an angle, a height) goes in as an assumption to confirm, and you ask the user, rather than
  picking it silently.

## The case

Before showing the user a case, run `check_enclosure` on the project. In a FreeCAD-only project, read case/ below as
the project root. It needs case/assembly.step with every part
placed and named (case parts, boards with their components, cables) and case/<part>.step for each printed part. It
reports parts that collide, openings in each shell, joints between case parts with a gap or a step, and part heights.
These are the defects a user otherwise finds by eye or after printing: one part standing above the one beside it, a
gap along a seam, a slot left open in a wall, a board pressed into a wall.

- The first run lists every opening. Put the ones that are meant to be there in case/enclosure.json (name, and a box,
  the part beside it, or the face), with the heights from the brief. Anything left is a hole to close.
- A step or gap that's designed (a rim, a shadow line) gets its own limit under joints, with the reason in the brief.
- `project_check` flags the case when the report is missing, older than the STEPs, or has errors.

## When to snapshot

Snapshot the part you're about to change (`paths: ["kicad/main"]`, `["case"]`; `["main"]` in a flat KiCad project),
or the whole project, when:

- the user has seen or approved the current state ("seems good", "PR good", a picked option), and the next change
  replaces it;
- the change is big or hard to undo by hand (re-placement, a new connector, reshaping the case);
- the user asks to keep it, or something is ordered (`label: "ordered"`, whole project, fab included).

Not before every small step. The routing tools (`route_critical_nets`, `autoroute_rest`, `finish_routing`) snapshot the
board themselves before changing it in place, and the footprint, symbol and part writers put a replaced file into
history/ instead of a `.bak`.

The label says what the state is or what comes next: `approved-layout`, `before-rework`, `ordered`.
The note (one sentence) goes into HISTORY.md: "User approved the placement; next, routing".

## Alternatives

When the user needs to choose between options, build them in `.cadmate/work/<option>/` (renders, a STEP, a board
copy), show them, apply the chosen one to the active project, and delete the work folder. Don't leave options in
the project, and don't make the user pick between folders. If an unpicked option might come back, snapshot it with a
label like `option-b`.

## Why it fits KiCad and FreeCAD, and where it doesn't

- **KiCad finds libraries relative to the project** (`${KIPRJMOD}/../lib/...`). A snapshot keeps the same relative
  paths and `project_snapshot` brings along the libraries a board folder references, so an old version opens in KiCad
  from history/ with its footprints and 3D models. Boards and schematics also embed their footprints and symbols, so
  they open even without the libraries. Absolute library or model paths break this: `project_check` flags them.
- **Never rename a KiCad project.** The schematic stores each symbol's reference under the project name; a copied or
  renamed project can come up with R?, U? references until it is re-annotated (KiCad's own Save As handles this; a
  file rename doesn't). Working in place means you never need to: the board is called
  `main` from the start. `project_check` flags a schematic whose annotations belong to another project name.
- **One board per folder.** KiCad pairs `.kicad_pcb`, `.kicad_sch` and `.kicad_pro` by name. A second board in the
  folder (`main-routed.kicad_pcb`) has no schematic to update from and no own rules unless its own `.kicad_pro` is
  copied beside it, which is how stray `-routed.kicad_pro` files appear.
- **Don't snapshot while KiCad has the file open and unsaved**: the snapshot is what's on disk. Ask the user to save,
  or use `kicad_pcb_save`, first. After `project_restore` the user has to reload the file in KiCad.
- **FreeCAD**: STEP files are self-contained. An `.FCStd` that links other documents (App::Link, assembly parts) stores
  relative paths when they're in the same tree; keep linked documents inside case/ (the root, in a FreeCAD-only
  project) so snapshots and `project_add_tool`'s move keep working.
- **fab/ is generated.** Re-export after every board change (`project_check` flags fab files older than the board).
  Snapshots include fab/ only when you snapshot the whole project, which is what you want for "ordered".
- **Git.** If the project is a git repository, commits do the same job better for text files (all KiCad files are
  text) and snapshots are still handy for the user to open an old version from Finder. Use both; don't commit
  `.cadmate/`.

## Cleaning up a project that sprawled

1. `project_init` on the folder, then `project_check`.
2. Ask the user which version of each board and case is current, if it isn't obvious from the thread. Don't guess from
   modification times alone.
3. Snapshot the whole folder as it is (`label: "before-cleanup"`), so nothing is lost.
4. Move the current files to their layout paths. Where the current board is a copy with a version name, copy its
   contents over the board named after the folder rather than renaming the KiCad project. A copied schematic keeps the
   old project name in its annotations: copy it the same way, then have the user open it in KiCad and check the
   references (`project_check` flags the mismatch). Delete the other versions
   (they're in the snapshot). Keep `tools/`: generator scripts are source, not intermediates.
5. `project_check` again until it's clean, run DRC on each board, re-export fab/.

Moving a project's own history to the Trash deletes the snapshots; say so before doing it.
