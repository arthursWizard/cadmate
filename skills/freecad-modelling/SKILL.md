# A FreeCAD part someone can change

A model can be correct and still be hard to change. The usual way it goes wrong, for a person or for you: a sketch
drawn on the top face of a pad, which moves or breaks when the pad changes; a size typed into six features; a fix
stacked on top of the feature it corrects instead of that feature being edited; thirty objects called `Sketch0xx` and
`Pocket0xx`. Every round adds to it, and after a few the user can no longer open the tree and change a wall thickness.

So the part is built as a tree a person can edit in FreeCAD, to the convention below, and `check_model_structure`
checks it. Knowing the rules isn't enough; run the check, and measure the shape after every change.

No formal standard covers how a feature tree is built. The convention here is the practice the major CAD vendors and
FreeCAD's own documentation share (sketch on planes, not faces; a master or layout sketch; key sizes in one place;
fillets last), arranged in the feature groups of the Resilient Modeling Strategy (RMS, a CAD-neutral method by Dick
Gebhard).

## Where a tree is the source, and where a script is

- **A printed or machined part** (case, lid, bracket, knob): the `.FCStd` tree is the source, and the user can edit
  it too. A script may build the first version (in `.cadmate/work/`, deleted once the `.FCStd` is saved); from then
  on, change the document. Rerunning a script would throw away the user's hand edits.
- **A component's 3D model for KiCad**: a script is the source (`kicad-3d-models`, `generate_part`). These are made in
  bulk from footprint values, only the STEP is used, and nobody edits them in FreeCAD; KiCad's own 3D library is
  generated by scripts for the same reason. The script's named dimensions are its parameter sheet.

## The convention

Each body's tree, top to bottom, in RMS's groups:

1. **Params** (one per document): a Spreadsheet named `Params`. Every size that drives the part has a cell with an
   alias (`wall`, `case_h`, `usb_z`) and, in the next column, where it came from (brief, datasheet, `read_footprint`,
   measured). A VarSet works too (FreeCAD 1.0+); the spreadsheet is preferred because it reads as a table with
   sources. Only expressions that read Params count: `7` typed as an expression is still a bare number.
2. **Reference**: the body's origin planes. Add a datum plane only when several sketches share a plane that isn't an
   origin plane; attach it to an origin plane with its offset from Params. Never attach anything to a face, edge or
   vertex of a feature; FreeCAD 1.x mitigates renumbered faces but doesn't remove the problem.
3. **Layout** (construction): a master sketch first, on an origin plane, with the shape's skeleton: the board outline,
   screw and key positions, the port centres. Other sketches take positions from it as external geometry, or from
   Params. FreeCAD can't use construction lines as external geometry: draw the layout's lines as normal geometry
   (the layout isn't padded, so they never become solid), or reference its points. A piece that must fit another
   uses the same Params entries, or a SubShapeBinder of the other piece's layout sketch (never of its faces).
4. **Core**: the main solid from the outline. Core features depend only on the reference planes, the layout and
   Params.
5. **Detail**: cut-outs, bosses, ribs, ports. Each depends on the core, the layout and Params, never on another
   detail's faces, so any one can be changed or deleted on its own.
6. **Modify**: patterns, mirrors, drafts.
7. **Finish**: fillets and chamfers, last. Nothing builds on a rounded edge. Prefer rounded corners drawn in a sketch
   over a fillet on a vertical edge.

### Why not sketch on the face?

Sketching on a face is common in commercial CAD, and it's fine for a model nobody will change. It costs three things
once the model does change:

- **The face is generated.** `Face6` is whatever the pad produced last time. Add a wall, a fillet or a draft upstream
  and the numbering can shift; FreeCAD 1.x follows most of these changes, but not all, and when it gets one wrong the
  sketch silently lands on another face or breaks.
- **The intent is lost.** A sketch on a face measures from that face's own corner. Make the part wider and a cut-out
  that should stay centred stays where it was. A sketch on a plane bound to Params (`Params.depth / 2` for the -Y
  wall, `0` for centred) moves with the wall, because both read the same number.
- **Order is locked.** A feature sketched on a face can't move above the feature that made the face.

So "a USB cut-out in the front wall" is written as: a sketch on the XZ plane, offset to the wall by the same Params
entry that places the wall, and a pocket a little deeper than the wall (see the example below). It reads the same in
the tree and keeps working when the case changes.

Also:

- **One PartDesign Body per printed piece**, named for the piece (`top`, `base`), the same names as the STEP pieces
  `check_enclosure` reads. Not Part-workbench boxes and booleans.
- **Fully constrained sketches.** Every point fixed to the origin, the axes, the layout sketch or a dimension.
  Dimensions that matter outside the sketch are bound to Params; one that is local to its sketch (a slot's end radius)
  gets a name so it reads as deliberate.
- **Names**: lowercase with hyphens, saying what each thing is: `layout`, `outline`, `shell`, `usb-cutout`,
  `screw-boss`, `lid-lip`, `wall-fillet`.
- **A cavity with a different floor than wall**: cut it as a pocket from the outline offset by `wall`, `case_h - floor`
  deep. PartDesign Thickness uses one value for walls and floor, so use it only when they're equal.

## Changing it

- **Edit the feature, don't stack a fix.** A wall that's too thin: change `wall` in Params. A port in the wrong place:
  change its Params entry or its sketch. Never add a pad that fills part of a pocket back in, or a pocket that trims a
  pad that came out too long. The check can't see this kind of stacking, so it's on you.
- A new feature is for a new piece of design (a vent, a second port), not for correcting an old one. Put it in its
  group: a new detail goes before the patterns and fillets (set the tip there, add it, set the tip back to the last
  feature).
- If a change can't be made by editing (the shape needs a different profile), redraw the feature's sketch in place, on
  the same plane, keeping its name.
- **Measure after every change**, before saying anything about it: each new or changed feature must add or remove
  material where you meant it. `check_model_structure` errors on a feature that changes nothing, but a cut in the
  wrong place still changes something; look at where.
- Live in the user's window (`freecad_live_edit`): one change per step, labelled with what changed. "Working live" in
  `kicad-3d-models` applies: `freecad_live_state` first, keep `user_changes`, tidy the view once at the end of a round.

In FreeCAD Python, a detail placed from Params, then measured. Plane normals aren't what you'd guess (in 1.1 the XZ
plane's normal points to -Y, so a positive offset moves the sketch toward -Y, and a pocket cuts against the normal),
so the measurement is not optional:

```python
import Sketcher

body = doc.getObject("Base")
xz = [f for f in body.Origin.OriginFeatures if f.Role == "XZ_Plane"][0]
sk = body.newObject("Sketcher::SketchObject", "Sketch")
sk.Label = "usb-cutout"
sk.AttachmentSupport = [(xz, "")]                   # an origin plane, not (pad, "Face6")
sk.MapMode = "FlatFace"
sk.setExpression(".AttachmentOffset.Base.z", "Params.depth / 2 + 1")  # 1 mm outside the -Y wall (normal is -Y)
# ... draw the cut-out's outline and constrain it, binding its sizes:
i = sk.addConstraint(Sketcher.Constraint("DistanceX", 0, 1, 0, 2, 9.0))
sk.renameConstraint(i, "usb_w")
sk.setExpression(".Constraints.usb_w", "Params.usb_w + 2 * Params.fit_gap")
pocket = body.newObject("PartDesign::Pocket", "Pocket")
pocket.Label = "usb-port"
pocket.Profile = sk
pocket.setExpression("Length", "Params.wall + 2")    # cuts against the normal (+Y): through this wall only, never ThroughAll
doc.recompute()
removed = pocket.BaseFeature.Shape.cut(pocket.Shape)  # what the pocket took away
result = {"removed_mm3": removed.Volume, "where": [round(v, 2) for v in (removed.BoundBox.XMin, removed.BoundBox.YMin,
          removed.BoundBox.ZMin, removed.BoundBox.XMax, removed.BoundBox.YMax, removed.BoundBox.ZMax)]}
```

If `removed_mm3` is 0 or `where` isn't the wall you meant, flip the offset's sign or the pocket's `Reversed`, and
measure again. To change a size later: `params.set(params.getCellFromAlias("wall"), "2.0")`, recompute, measure.

## The check

`check_model_structure` reads the tree (a saved `.FCStd` by path, or the user's window without one) and reports:

- **error**: a sketch, datum, external geometry or binder that references a generated face, edge or vertex; a sketch
  not fully constrained; a feature that changes nothing; a feature in error; sizes with no Params sheet at all. Fix
  these before showing the part.
- **warning**: values and attachment offsets not from Params, and unnamed sketch dimensions not bound; fillets or
  chamfers before other features; default names; more than one parameter sheet; features suppressed or past the tip;
  a very long body; a sketch on a binder's face; solids with no history (`Part::Feature`) or Part-workbench CSG where a
  printed piece should be a Body. Fix them unless there's a reason, and say the reason. An imported board inside an
  `App::Part` isn't flagged; a single imported solid at the top level is, and is fine.
- **info**: named local sketch dimensions; unused sketches (delete leftovers; a layout sketch used by others is fine).

Run it after every round of modelling, with `check_enclosure` for a case, and before telling the user a step is done.
Its report sits beside the `.FCStd` (`<name>-structure.json`), and `project_check` flags it when it's missing, older
than the document, or failing.

## Tidying a model that's already messy

1. `project_snapshot` with a label like `before-restructure`.
2. `check_model_structure`, and note each piece's bounding box (`freecad_live_state`) and volume (`Shape.Volume`):
   the tidy must not change the shape.
3. Add the Params sheet and move the sizes into it, binding each feature, offset and sketch dimension as you go.
4. Add a layout sketch if the part has none, and re-attach face-attached sketches to an origin or datum plane at the
   same position (attachment offset from Params), working from the first feature down; recompute and compare after
   each.
5. Fold stacked fixes into the feature they correct, move fillets and chamfers to the end, and delete what's left
   over (unused sketches, suppressed features, features past the tip).
6. Name everything.
7. Check again, and compare volumes and boxes with step 2. If a body has more errors than features worth keeping,
   rebuilding it cleanly from Params is often faster: ask the user first, since it replaces their tree.
